## 개요

AI 모델이 찾아낸 탐지 결과를 사람이 확인하고 관리하는 웹 서비스입니다. 탐지된 객체를 이미지와 지도 위에 보여 주고, 검수자가 목록에서 빠르게 찾아 판단할 수 있게 하는 것이 핵심이었습니다. 프론트엔드를 주도했습니다.

## 문제

검수자는 하루에 많은 탐지 결과를 봅니다. 한 건을 판단하려면 "무엇이 탐지됐나(이미지)", "어디서 탐지됐나(지도)", "모델이 얼마나 확신하나(신뢰도)"를 함께 봐야 합니다. 이 세 가지가 서로 다른 화면에 흩어져 있거나, 한쪽에서 고른 것이 다른 쪽에 반영되지 않으면 검수 속도가 떨어지고 실수가 생깁니다.

## 목표

- 많은 탐지 결과와 상태 정보를 한눈에 읽히게 표현
- 목록·이미지·지도 사이의 선택, 강조, 이동 흐름을 예측 가능하게 구성
- 정보 밀도를 조절해 검수자의 시선 흐름 유지

## 한 일

### 탐지 결과 보기

- 탐지 데이터 목록과 상세 조회
- 이미지 위 Bounding Box와 ROI(관심 영역) 시각화
- 객체별 탐지 결과, 신뢰도, 라벨 표시와 정렬

### 지도

- 지도 기반 위치 검색
- 위치별 탐지 이력 확인

### 찾기와 다국어

- 검색, 필터링, 페이지네이션
- 한국어·영어·일본어 다국어 지원

### 연동과 운영

- API 연동과 응답 데이터 파싱
- 오류 처리와 운영 중 수정

## 직접 내린 결정

- **선택 상태를 한곳에 두기.** 지금 고른 객체, 걸린 필터, 지도 위치를 각 화면이 따로 들고 있지 않고 한곳에서 관리하게 했습니다. 목록에서 고르면 이미지와 지도가 같이 따라오고, 반대 방향도 같은 규칙을 따릅니다.
- **같은 값은 어디서나 같은 모양으로.** 신뢰도와 라벨은 목록, 이미지, 지도에서 같은 색과 표기를 쓰게 맞췄습니다.
- **지도는 사용자가 움직인 만큼만.** 데이터가 바뀌었다고 지도가 마음대로 이동하면 검수자가 보던 위치를 잃습니다. 사용자가 고른 것에만 지도가 반응하게 했습니다.

## 배운 점

- 상태 설계가 UI 복잡도를 결정한다. 선택된 객체, 필터, 지도 위치가 서로 어떻게 묶이는지를 먼저 정해야 화면이 단순해진다.
- 일관성이 신뢰를 만든다. 같은 신뢰도와 라벨이 목록과 이미지, 지도에서 같은 모양으로 보여야 검수자가 결과를 믿는다.
- 지도 인터랙션은 예측 가능해야 한다.
