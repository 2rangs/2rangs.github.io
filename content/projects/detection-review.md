## 개요

AI가 도로 위 위험물을 찾아내면 사람이 그 결과를 확인해야 합니다. 이 서비스는 그 검수 화면으로, 검수자와 국내외 고객이 씁니다. 탐지 목록, 상세 정보, 이미지, 위치를 한 흐름으로 이어 한 건씩 빠르게 판단할 수 있게 하는 것이 목표였고, 화면은 한국어·영어·일본어로 제공합니다. Vite, Nginx, REST API도 함께 썼습니다.

## 검수 화면과 지도

탐지 데이터 목록에서 한 건을 고르면 상세 정보, 이미지, 위치가 함께 보이도록 화면을 연결했습니다. 목록은 탐지 유형, 검수 상태, 기간 같은 조건을 조합해 걸러 볼 수 있습니다. 이미지 위에는 AI가 찾은 객체의 Bounding Box와 라벨을 그리는데, 이미지와 탐지 좌표가 어긋나지 않도록 오버레이를 이미지 좌표 기준으로 처리했습니다. 한 이미지에서 객체가 여러 개 탐지된 경우에는 객체별로 표시 여부를 제어할 수 있게 했습니다.

지도는 OpenLayers로 만들었습니다. 탐지 데이터의 위도·경도를 지도 객체와 연결하고, 지도 검색과 탐지 상세 정보의 상태를 연동해서 지도에서 고른 탐지와 이미지 위의 탐지 결과가 같은 흐름 안에서 보이게 했습니다.

## 국내외 환경 대응

같은 서비스를 국내와 해외 고객이 함께 쓰다 보니 번역 말고도 환경마다 다른 것이 많았습니다. 고객마다 API 환경이 달라 운영 환경별로 설정을 분기했고, 서비스 환경에 따라 지도 공급자와 지도 데이터도 달라서 이에 맞게 기능을 나눴습니다. 이미지 스토리지도 접근 방식과 경로가 환경마다 달라 이미지 요청을 환경별로 처리했습니다. 언어 리소스는 한국어·영어·일본어를 관리하면서, 공통 리소스와 로케일별 표현을 분리해 두었습니다.

## 구조 전환

기존 Vue 기반 UI를 Quasar 중심으로 옮기면서 컴포넌트 구조와 공통 UI를 다시 짰고, 검수 업무 흐름에 맞춰 화면 구성도 고쳤습니다. 개발 환경은 Vite 8 기반으로 바꿨습니다. 이어서 [공통 디자인 시스템](/projects/design-system/)으로 화면을 개편하는 PoC를 진행해, 기존 기능을 유지한 채 구조를 옮길 수 있는지 검증했습니다.

## 문제 해결

### 페이지를 옮길 때 목록 요청이 두 번 더 나가던 문제

Quasar로 옮기던 중, 페이지를 이동할 때마다 목록 조회 요청이 두 번씩 더 나가는 문제가 있었습니다. 검색 컴포넌트 안에서 검색 조건을 `watch`로 지켜보다가, 값이 바뀔 때마다 검색을 실행하는 구조가 원인이었습니다.

검색 조건을 별도의 store로 옮겨 조건이 바뀌는 곳을 한 군데로 모으자 중복 요청이 사라졌습니다. 이 과정은 [2024년 회고](/blog/2024-retrospective/)에도 적었습니다.

### 이미지 존재 확인 요청 문제

운영 중 이미지 요청에서 문제가 생겼습니다. 이미지가 있는지 먼저 확인하는 데 HEAD 요청을 쓰고 있었습니다. 스토리지와 브라우저 요청 정책이 HEAD 요청을 어떻게 다루는지 검토한 뒤, 확인 요청을 GET으로 바꿔 해결했습니다.

이 외에도 배포 환경에 따라 생기는 API 연동 오류, 이미지 요청 실패, 인증 문제를 분석하고 대응했습니다.

## 현재 상태와 배운 점

검수 서비스의 프론트엔드 구현과 운영을 맡고 있습니다. 디자인 시스템 기반의 전체 UI 개편은 PoC 단계까지 진행했습니다.

중복 요청 문제를 겪으며, 조건이 바뀌는 곳이 여러 군데면 요청도 그만큼 여러 번 나간다는 걸 확인했습니다. 그 뒤로는 상태를 어디에 둘지부터 정합니다. 또 같은 탐지 결과가 목록과 이미지, 지도에서 같은 모양으로 보여야 검수자가 결과를 믿고 판단할 수 있었습니다.
