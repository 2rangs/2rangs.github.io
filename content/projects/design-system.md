## 배경

프로젝트와 개발 환경이 달라질 때마다 스타일이 어긋나고, 같은 컴포넌트를 반복해서 만들고 있었습니다. 화면을 하나씩 고치는 대신, 여러 프로젝트가 같이 쓰는 부품을 만들기로 했습니다.

## 한 일

- KRDS를 기반으로 공통 디자인 토큰과 UI 표준 설계
- Vue 3와 React 환경별 컴포넌트 구조 설계 및 공통 컴포넌트 개발
- Storybook 문서화와 시각 회귀 테스트 구성
- 자동화 테스트와 브라우저 품질 게이트 구축
- npm 패키지 빌드·배포, 모노레포와 CI/CD 구성 개선

## 직접 내린 결정

- UI 불일치를 풀기 위한 기준으로 KRDS 채택
- 프레임워크별 구현 분리
- 테스트와 검증을 중심에 둔 개발 방식

## 배운 점

- 예쁜 UI보다 일관된 UI가 더 어렵다.
- 디자인 토큰은 유지보수의 핵심이다.
- 명확한 기준이 개발 속도를 만든다.

## 상태

개발·검증과 내부 적용 단계까지 진행했습니다.
