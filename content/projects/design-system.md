## 개요

여러 관제·관리 서비스가 같이 쓰는 사내 디자인 시스템입니다. KRDS(대한민국 정부 디자인 시스템)를 기반으로 디자인 토큰과 UI 표준을 정하고, Vue 3와 React 두 환경에서 쓸 수 있는 공통 컴포넌트를 만들었습니다. 설계부터 개발, 문서화, 배포 체계까지 주도했습니다.

## 배경

프로젝트와 개발 환경이 달라질 때마다 스타일이 어긋나고, 같은 컴포넌트를 반복해서 만들고 있었습니다. 화면을 하나씩 고치는 대신, 여러 프로젝트가 같이 쓰는 부품을 만들기로 했습니다.

## 목표

- 일관성을 유지할 수 있는 UI 기준 수립
- 다크 모드를 포함한 토큰 기반 설계
- 재사용 가능한 컴포넌트 패턴 정리

## 한 일

### 기준과 토큰

- KRDS를 기반으로 공통 디자인 토큰과 UI 표준 설계
- 색, 간격, 글자 크기 같은 값을 토큰으로 정의해 컴포넌트가 직접 값을 쓰지 않게 구성

### 컴포넌트

- Vue 3와 React 환경별 컴포넌트 구조 설계
- 공통 컴포넌트 개발

### 품질과 문서

- Storybook 문서화와 시각 회귀 테스트 구성
- 자동화 테스트와 브라우저 품질 게이트 구축

### 배포와 운영

- npm 패키지 빌드·배포
- 모노레포와 CI/CD 구성 개선

## 직접 내린 결정

- **UI 불일치를 풀 기준으로 KRDS 채택.** 처음부터 기준을 새로 만드는 대신 검증된 공공 표준 위에서 시작했습니다.
- **프레임워크별 구현 분리.** 토큰과 규칙은 공유하고, 컴포넌트 구현은 Vue 3와 React 각각의 방식에 맞췄습니다.
- **테스트와 검증을 중심에 둔 개발 방식.** 여러 프로젝트가 같이 쓰는 만큼, 바뀐 것이 다른 화면을 깨뜨리지 않는지 자동으로 확인하는 것을 먼저 갖췄습니다.

## 배운 점

- 예쁜 UI보다 일관된 UI가 더 어렵다.
- 디자인 토큰은 유지보수의 핵심이다.
- 명확한 기준이 개발 속도를 만든다.

## 상태

개발·검증과 내부 적용 단계까지 진행했습니다. 디자인 시스템을 만들며 정리한 생각은 블로그 글 [디자인 시스템이 필요한 이유와 구축 전략](/blog/design-system-basics/)에, 패키지 구성을 고민하며 정리한 내용은 [모노레포란 무엇인가](/blog/what-is-monorepo/)에 적었습니다.
