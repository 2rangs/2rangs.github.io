## 개요

도로 위험 분석 서비스에서 분석 데이터를 조회하는 화면과, 데이터가 많을 때 느려지던 조회 성능 개선을 맡았습니다. 기능 단위로 참여했습니다.

## 문제

분석 데이터가 쌓일수록 조회 화면이 느려졌습니다. 화면 렌더링보다 먼저, 많은 데이터를 한 번의 요청으로 받아 오는 방식이 병목이었습니다. 응답이 올 때까지 사용자는 아무것도 볼 수 없었습니다.

## 한 일

### 조회 성능

- 한 번에 받던 대량 조회 요청을 여러 개로 나누고, 나눈 요청을 병렬로 보내도록 변경
- 요청 하나가 무거워지지 않으니 응답이 고르게 들어오고, 일부 요청이 실패해도 전체를 다시 받을 필요가 없게 됨

### 조회 화면

- 분석 데이터 조회와 필터링
- 분석 결과 시각화 개선

### 수정과 문서

- 지도와 이미지 위 Bounding Box 위치가 어긋나던 오류 수정
- 맡은 기능의 문서화

## 배운 점

- 데이터가 많아질수록 화면보다 요청 방식이 먼저 병목이 된다.
- 성능 개선은 어디가 느린지 재 보는 것에서 시작한다. 추측으로 렌더링부터 손대면 시간을 잃는다.
