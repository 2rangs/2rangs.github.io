## 두 번 만든 프로젝트

첫 번째 버전(2026년 2\~3월)은 평범한 도감이었습니다. 목록을 페이지 단위로 PokeAPI에서 받아 오고, 카드 하나마다 상세 정보를 다시 요청했습니다. 필터 하나를 바꿀 때마다 네트워크를 기다려야 했고, 1,000개가 넘는 포켓몬을 "배울 수 있는 기술"로 거르는 건 사실상 불가능했습니다.

두 번째 버전(2026년 11월)은 구조부터 다시 짰습니다. 목록·검색·필터에 필요한 데이터를 미리 만들어 함께 배포하고, 한국어·영어·일본어를 지원하고, UI는 Astryx 디자인 시스템 위에서 다시 만들었습니다. 세대 타임라인과 도구·나무열매 화면도 이때 더했습니다.

한동안은 팀 빌더와 배틀 화면, CPU끼리 싸우는 배틀 데모, 데미지 계산기도 들어 있었습니다. 동작은 했지만 도감 안에 반쯤 만든 게임이 붙은 모양이라 모두 지우고 외부 배틀 엔진 의존성도 뺐습니다. 예전 `/battle`, `/calc` 링크는 404 대신 첫 화면으로 보냅니다.

## 구조

### 데이터: 미리 만들 것과 그때 받을 것

목록·검색·필터처럼 자주 거르는 데이터만 미리 만들고, 한 번 보고 마는 데이터는 그때 받습니다.

| 구분 | 데이터 | 방식 |
|---|---|---|
| 미리 만들어 함께 배포 | 목록·검색·필터용 포켓몬, 기술, 특성, 도구·나무열매, 3개 언어 이름 | 스크립트가 PokeAPI REST와 CSV 덤프에서 모아 JSON으로 저장(약 4.0MB) |
| 미리 만들어 두고 필요할 때 받기 | PokeAPI에 없는 한국어 도감 설명(포켓몬 위키) | 종마다 작은 파일 하나(1,023개, 합계 4.5MB). 상세 화면이 그 종의 파일만 받는다 |
| 상세 화면에서 요청 | 도감 설명, 진화 단계, 세대별 기록(`past_types`·`past_abilities`·`past_stats`), 울음소리 주소 | TanStack Query로 요청하고 캐시 |

이름·번호 조회표는 JSON을 불러올 때 한 번만 만들어 모든 화면이 같이 씁니다. `mr-mime-galar` 같은 폼 이름에서 기본 종(`mr-mime`)을 찾을 때는 알려진 이름 중 가장 긴 앞부분부터 맞춰 봅니다.

### 상태: 남아야 하는 기간에 따라 나누기

| 상태 | 저장 위치 | 이유 |
|---|---|---|
| 언어 | localStorage (Zustand) | 다음에 와도 같은 언어로. 첫 방문은 브라우저 언어를 따름 |
| 도감 필터, 불러온 페이지 수 | sessionStorage (Zustand) | 상세를 보고 돌아와도 보던 자리 그대로, 탭을 닫으면 초기화 |
| 기술·특성·도구·스프라이트 필터, 상세의 탭·세대·암수 | URL 쿼리 | 링크로 공유 가능. `/pokemon/35?gen=5` |
| PokeAPI 응답 | TanStack Query | 같은 포켓몬을 다시 열면 바로 |

이 블로그 저장소가 Pokestra의 `main`을 받아 `/portfolio/pokestra/` 경로로 빌드해 함께 게시합니다. 빌드는 Pokestra 저장소만으로 끝납니다.

## 핵심 구현

### 1. 세대 타임라인

세대별 스프라이트와 울음소리, 세대마다 바뀐 타입·특성·종족값은 보통 여러 사이트에 흩어져 있습니다. 상세 화면에서 세대 하나를 고르면 머리말의 스프라이트·타입·특성·종족값이 그 세대 기준으로 바뀌고, 현재와 다른 항목에는 "N세대에 변경"이 붙습니다(예: 픽시는 5세대까지 노말, 6세대부터 페어리).

새 데이터는 만들지 않았습니다. 상세 화면이 이미 받는 PokeAPI 응답의 `past_*` 기록은 "N세대까지는 이 값"이라는 뜻이라, 고른 세대 G에 대해 `N >= G`인 기록 중 가장 이른 것을 쓰고 없으면 현재 값을 씁니다. 이 계산은 `typesAt`·`abilitiesAt`·`statsAt`·`spriteAt`·`cryAt` 순수 함수로 분리해 실제 응답 픽스처(피카츄, 삐삐)로 테스트했습니다.

1세대는 특공/특방 대신 "특수" 한 칸이고, 1·2세대에는 "특성은 3세대부터"라고 안내하며, 3·4세대에는 숨겨진 특성이 없습니다. 울음소리는 1\~5세대면 옛날 것을, 6세대 이상이면 최신 것을 먼저 냅니다. 선택 줄은 등장 세대부터만 보이고 다른 폼에서는 숨깁니다. 타입 상성만 현재 기준이고, 화면에 그렇게 표시해 어느 세대 기준인지 헷갈리지 않게 했습니다.

### 2. 빈 공간 줄이기

빈 공간이 많아 한 화면에서 얻는 정보가 적었습니다. 테마의 간격 값을 줄이면 버튼까지 작아지고 배치 문제는 그대로라 화면마다 배치를 다시 짰습니다.

가장 중요한 정보는 왼쪽 위, 다음은 같은 줄 오른쪽, 그다음은 다음 줄에 놓아 스크롤 전에 그 화면의 일이 끝나게 했습니다. 마우스 동선(Fitts의 법칙)을 줄이려고 조작은 그것이 바꾸는 결과 바로 위에 두고, 표는 행 전체를 클릭 영역으로 만들고(텍스트 선택·새 탭 열기는 그대로), 필터 바는 결과가 바뀌어도 밀리지 않게 고정했습니다. 더 보기와 이전/다음 포켓몬은 마지막으로 누른 자리 근처에 있습니다. 훑어보는 데이터는 표로(라벨은 흐리게, 값은 진하게, 숫자는 오른쪽 정렬), 읽는 글은 한 줄 65자 안팎으로 맞췄습니다.

글자 크기와 휴대폰의 44px 터치 영역은 두고 빈 공간과 이미지 칸만 줄였습니다. 바로 이해되지 않는 수치는 상세로 옮겼습니다. 도구 목록에는 이름·분류·한 줄 설명·맛만 있고, 자연의은혜나 내던지기 위력은 상세 화면에서 짧은 설명(ⓘ)과 함께 나옵니다. `/`를 누르면 검색창으로, 상세 화면에서는 ←/→로 이전·다음 포켓몬으로 갑니다.

### 3. 이미지 로딩

포켓몬 이미지를 20곳 가까이에서 제각각 그리고 있었고, 28\~40px 자리에 475px 공식 일러스트를 받는 곳도 있었습니다. 이를 `PokeImage` 컴포넌트 하나로 모았습니다.

```ts
// ≤40px: [SV 박스 아이콘, 7세대 박스 아이콘, 도트, 아트워크]
// ≤64px: [도트, 아트워크], >64px: [아트워크, 도트]
const list = displayPx <= SPRITE_MAX_PX ? [sprite, art] : [art, sprite]
if (opts.back) list.unshift(backSpriteUrl(id))
else if (displayPx <= BOX_ICON_MAX_PX) list.unshift(...boxIconUrls(id))
return [...new Set(list.filter(Boolean))]
```

표시 크기에 맞는 후보를 순서대로 시도하고(40px 이하는 알아보기 쉬운 PC 박스 아이콘부터), 모두 실패하면 빈 자리를 남깁니다. 크기를 고정하고 로드 전에는 같은 크기의 스켈레톤을 보여 줘서 레이아웃이 밀리지 않습니다. 상세 화면의 메인 아트워크는 우선순위를 높여 받고, 이전/다음 포켓몬 아트워크는 브라우저가 한가할 때 미리 받습니다. 페이지를 옮길 때 바닥글이 위아래로 튀던 것은 지연 로딩 중의 대체 화면에 높이가 없어서였고, 실제 화면과 비슷한 높이를 잡아 둔 공통 스켈레톤으로 고쳤습니다.

### 4. 검색창 하나로 세 언어와 번호 찾기

검색창에는 "피카츄", "pikachu", "ピカチュウ", "ぴかちゅう", "Mr. Mime", "mr-mime", "#25", "No.25"가 모두 들어옵니다. 검색어와 이름을 같은 규칙으로 정규화해 비교합니다.

```ts
function toKatakana(s: string) {
  return s.replace(/[ぁ-ゖ]/g, (c) => String.fromCharCode(c.charCodeAt(0) + 0x60))
}
export function norm(s: string) {
  return toKatakana(s.normalize('NFKC').toLowerCase()).replace(/[\s\-_.'’:・]+/g, '')
}
```

전각·반각을 맞추고(NFKC), 히라가나를 가타카나로 바꾸고, 공백·하이픈·점 같은 구분자를 지웁니다. 검색 색인은 처음 한 번만 만들고, 한국어 포켓몬 이름과 기술 이름은 초성 색인도 만들어 "ㄹㅈㅁ"으로 리자몽을 찾습니다. 숫자는 전국도감 번호로 찾아서 같은 번호의 폼도 함께 나옵니다. 입력은 `useDeferredValue`로 처리해 타이핑은 바로 반응하고 목록은 뒤따라 갱신되며, 이름 정렬용 `Intl.Collator`는 언어별로 하나만 만들어 재사용합니다.

### 5. 로컬 데이터로 계산하는 실능치

실능치 패널(Lv50/Lv100 최소·무보정·최대)은 처음에 외부 배틀 엔진의 계산 함수를 썼습니다. 의존성을 빼면서 표준 공식을 순수 함수로 옮기고, 알려진 값으로 단위 테스트를 붙였습니다.

```ts
/** HP: ⌊(2B + I + ⌊E/4⌋) · L / 100⌋ + L + 10. 껍질몬(종족값 1)은 항상 1 */
export function calcHp(base: number, level: number, iv: number, ev: number): number {
  if (base === 1) return 1
  return Math.floor(((2 * base + iv + Math.floor(ev / 4)) * level) / 100) + level + 10
}
```

최소는 개체값 0·노력치 0·하락 성격, 무보정은 31·0·무보정, 최대는 31·252·상승 성격입니다. 로컬 종족값만으로 계산하므로 패널이 다른 데이터를 기다리지 않습니다.

### 6. 색은 타입 배지와 능력치 막대에만

카드 배경까지 타입 색으로 칠한 버전은 화면이 시끄럽고 정보 구분이 오히려 흐려져서 버렸습니다. 타입 배지는 게임에서 익숙한 색과 아이콘을 따랐습니다. 18개 타입 색은 `:root`를 덮어쓰지 않고 Astryx `neutral` 테마를 확장한 커스텀 `pokestra` 테마의 토큰으로 만들어 라이트·다크 모드가 함께 바뀝니다. 생성 스크립트 하나가 테마 값·Tailwind 유틸리티(`bg-type-fire` 등)·클래스 표를 같이 씁니다. 불꽃과 땅처럼 비슷해 보이는 색은 아이콘과 흰 글자·옅은 그림자로 구분합니다.

능력치 막대는 30/60/90/120/150 구간마다 색을 달리하고, 옆에 "전체 1,025종 중 상위 N%"(낮은 쪽은 하위 N%)를 소수 첫째 자리까지 붙였습니다. 리자몽 특공 109는 상위 12.0%, 해피너스 HP 255는 0.1% 대신 "단독 1위"로 나오고, 같은 값이 여럿이면 "공동 1위"입니다.

### 7. 빠진 번역은 컴파일 오류로

```ts
export function defineMessages<const K extends string>(m: {
  ko: Record<K, string>; en: NoInfer<Record<K, string>>; ja: NoInfer<Record<K, string>>
}): Messages<K> { return m }
```

키 목록은 한국어 문구에서만 정해지고, `NoInfer`가 영어·일본어 쪽에서 키가 늘어나지 않게 막습니다. 영어나 일본어에 키가 하나라도 빠지면 타입 검사가 실패합니다. 실행 중에 문구가 없으면 한국어, 그다음 키 이름을 대신 보여 줍니다.

### 8. 긴 목록 나눠 그리기

긴 목록은 60개씩 그리고, 끝에 둔 감시 요소가 화면 600px 앞에 오면 다음 묶음을 그립니다. 필터가 바뀌면 처음 개수로 돌아가야 하는데, `useEffect`로 처리하면 렌더링이 한 번 더 일어납니다. 그래서 개수와 함께 어떤 필터 조합에서의 개수인지를 저장해 두고, 렌더링 중에 필터가 달라졌으면 바로 처음 개수를 씁니다.

### 9. 첫 화면 다시 짜기

종족값 TOP, 전설, 최신 세대… 를 가로 줄로 늘어놓은 첫 화면은 도감 목록의 축소판이어서, 도감에 들어오는 방법이 서로 다른 세 덩어리로 바꿨습니다.

실루엣 퀴즈는 날짜로 정해지는 오늘의 포켓몬(누구에게나 같음)을 검은 실루엣으로 보여 주고 세 언어 이름이나 초성으로 맞히게 합니다. 힌트는 타입·세대이고, 맞히면 그림이 드러나며 상세로 이어지고, 연속 정답 일수를 셉니다. 판정·문제 고르기·연속 기록은 순수 함수로 테스트했습니다. 찾아보기에는 검색, 자주 찾는 포켓몬, 타입·세대 칩이 있고, 칩을 누르면 그 필터가 걸린 도감으로 갑니다. 종족값 지도는 전체 종을 SVG 산점도로 그립니다. 축은 6가지 능력치, 공격력(공격·특공 중 높은 값), 합계 중에서 고르고, 점 크기는 합계, 색은 타입입니다.

지도는 읽는 법을 화면에 직접 적었습니다. 축 고르기는 "→ 오른쪽일수록 높은 [공격력] · ↑ 위쪽일수록 높은 [스피드]"처럼 문장으로 바꾸고, 두 축을 한 번에 바꾸는 추천 비교(빠른 공격수, 단단한 방어형, 체력과 방어, 강한데 빠른)를 두었습니다. 그래프 네 귀퉁이에는 "↗ 둘 다 높음", "↖ 스피드만 높음", "↙ 둘 다 낮음" 같은 뜻을, 아래에는 "점 1개 = 포켓몬 1마리 · 클수록 종족값 합계가 높음 · 색 = 타입"이라는 범례를 적었습니다. 점에는 브라우저 기본 말풍선 대신 그림·이름·타입·두 값이 담긴 정보 카드를 붙였습니다. 데스크톱에서는 올리면 카드가, 누르면 상세가 열리고, 휴대폰에서는 탭하면 카드와 "상세 보기" 버튼이 나옵니다.

![종족값 지도: 드래곤 타입을 강조하고 점에 마우스를 올린 모습](/img/projects/pokestra/stat-map.webp)

타입을 고르면 그 타입만 남고 나머지는 흐려지며, 상위 3마리 이름표는 서로, 그리고 강조 고리와 겹치지 않는 자리를 찾아 붙습니다. viewBox로 줄이지 않고 칸 너비의 실제 픽셀로 그려서 휴대폰에서도 글자가 같은 크기로 보입니다.

### 10. 뒤로 가면 보던 자리로

긴 도감을 내리다 상세를 보고 돌아오면 맨 위로 튕겼습니다. 새로 이동할 때(PUSH)는 맨 위로, 뒤로/앞으로(POP)는 경로별로 저장해 둔 위치로 가되, 무한 스크롤 목록이 충분히 길어질 때까지 잠깐 기다렸다가 맞춥니다.

### 11. 폼 선택과 도트 크기

메가진화·리전폼 같은 폼은 개요 탭 맨 아래의 글자 칩으로 골랐는데, 그림을 보고 고르도록 머리말 그림 바로 아래에 폼마다 그림 타일을 두었습니다. 지금 폼은 테두리로 표시하고, 마우스를 올린 타일의 이름은 위 줄에 보여 줍니다. 피카츄처럼 폼이 17개여도 한 번에 다 보입니다.

![리자몽 상세: 그림 아래 폼 타일(메가 X에 마우스를 올린 모습)](/img/projects/pokestra/detail-forms.webp)

스프라이트는 96px 원본을 72\~80px 칸에 넣고 있어서 원본보다 작게 보였습니다. 원본 크기(56·64·80·96px)를 읽어 칸에 들어가는 가장 큰 정수배로 그리게 바꿨습니다(96px → 2배, 1\~3세대 56·64px → 3배). 정수배라 픽셀이 고르게 커지고 흐려지지 않습니다. 박스 아이콘은 2배까지만 키웁니다.

### 12. 빠진 한국어 데이터 채우기

한국어 화면 곳곳에 영어가 섞여 있었습니다. 하나씩 따라가 보니 대부분은 한국어 데이터가 없는 게 아니라 가져오는 과정에서 빠진 것이었습니다.

| 빈칸 | 원인 | 해결 |
|---|---|---|
| 폼 이름 121개가 영어(Attack, Rock Star…) | 토큰 사전으로 폼 이름을 만들었는데 사전에 없는 폼 | PokeAPI `pokemon_form_names`의 공식 이름(어택폼, 붉은 달…)을 쓰고, 짧은 사전 라벨("메가 X")은 사전 라벨이 다 옮겨졌을 때만. 공식 데이터에도 한국어가 없는 37개는 한국어판 표기로 직접 |
| 도구 설명 58개 | PokeAPI에 한국어가 있었는데 생성 스크립트가 놓침 | 다시 받아 채움 |
| 특성 설명 7개(포켓몬 챔피언스 신규) | PokeAPI의 챔피언스 데이터는 영어·일본어뿐 | 챔피언스 한국어판 문구로 |
| 기술 설명 23개(스타모빌·다크포켓몬 전용) | 어느 언어로도 설명이 없음 | 게임 문체로 직접 작성 |
| 도감 설명이 영어로 뜸 | 최신 작품에 영어 설명만 있으면 그게 기본값 | 사용자 언어 설명을 먼저 고르고, 영어는 목록에서 선택 |

다시 빠지지 않도록 폼 이름(한·일)과 기술·특성·도구 설명 중 하나라도 한국어가 비면 실패하는 테스트를 붙였습니다.

### 13. 포켓몬 위키에서 한국어 도감 설명 가져오기

PokeAPI의 한국어 도감 설명은 6세대(X·Y)부터만 있고, 메가진화·리전폼 같은 모습별 설명은 영어뿐이었습니다. 그래서 루카리오의 4·5세대 설명이나 메가루카리오의 설명은 영어로 나왔습니다. 한국어 [포켓몬 위키](https://pokemon.fandom.com/ko/)에는 1세대부터 모습별 설명까지 정리돼 있어서, 이를 한 번 모아 데이터로 만들었습니다.

위키의 일반 페이지에는 봇 확인이 걸려 있어 우회하지 않고 MediaWiki 공개 API로 문서 원문(wikitext)만 읽었습니다. 1,025종 문서는 요청 사이사이 쉬어 가며 한 번씩만 받아 캐시했고, 다시 만들 때는 위키에 요청하지 않습니다.

문서에는 새 틀(`{{도감/세대}}`·`{{도감/설명N}}`·`{{도감/폼|메가루카리오}}`)과 옛 틀(`{{포켓몬도감설명|금 도감=…}}`)이 섞여 있습니다. 처음에는 새 틀만 읽어 절반 가까운 종이 빠졌고, 둘 다 읽게 고친 뒤 결과를 세어 보며 "등장하지 않음" 같은 자리 표시, `[[문서|글]]` 링크 안의 `|` 때문에 잘린 설명, 남은 HTML 태그를 찾아 하나씩 걸렀습니다.

위키의 "메가리자몽X", "알로라의 모습", "오리지널캡 피카츄"는 공식 폼 이름과 키워드(메가·알로라·거다이맥스·오리진…)로 데이터의 모습에 짝지었습니다. 짝이 없는 것은 대개 기본 모습(킬가르도 실드폼 등)이나 데이터에 없는 꾸밈 모습(사철록의 계절)이라 종의 설명으로 넣었습니다. 결과는 1,023종, 설명 16,457개이고, 5세대까지의 649종 모두 4·5세대 한국어 설명이 생겼습니다. 위키에서 온 설명에는 "포켓몬 위키", 한국어판이 나오지 않은 작품(1~3세대, 크리스탈)의 설명에는 "한국어판 미발매 · 위키 번역"을 붙이고, 목록 아래에 출처와 라이선스(CC BY-SA 3.0)를 적었습니다.

"모두 보기"를 누르면 위키처럼 세대별로, 그 안에서 종의 설명 다음에 모습별 설명이 이어지고, 같은 글이 여러 세대에 실렸으면 세대마다 한 줄씩 나옵니다. 작품은 공식 로고 대신 작품 고유 색 배지(R·B·Sw·ZA…)로 표시합니다. 세대를 고르면 그 세대(없으면 리메이크 작품)의 설명이, 반대로 설명을 고르면 그 작품의 세대와 도트가 따라옵니다.

같은 날, 데이터 스냅숏이 레전드 Z-A·메가 차원 러시 이전 것이라 새 메가진화 49종(메가픽시, 메가망나뇽, 메가루카리오Z, 메가라이츄X·Y…)이 빠져 있는 것도 발견했습니다. 전체 데이터를 새로 만드는 원래 스크립트는 그동안의 한국어 보정을 덮어쓰기 때문에, 없는 id만 덧붙이는 스크립트를 따로 만들었습니다.

## 그 밖에 고친 것들

휴대폰에서 메뉴·언어 전환·맨 위로 버튼이 누르기 어려웠던 것은 터치 영역이 44px보다 작아서였고, 44px로 키우고 고정 머리말 높이에 맞춰 sticky 위치를 정렬했습니다. 스프라이트 타일에서 한 줄 말줄임으로 양쪽이 잘리던 긴 폼 이름은 두 줄까지 줄바꿈하고, 세부가 많아 뭉개지던 16px 파비콘은 단순한 SVG로 다시 그렸습니다. 기술 설명 400여 개가 "사용할 수 없는 기술입니다"로 나오던 것은 최신 버전(소드·실드)에서 빠진 Z기술·레츠고 전용 기술 등의 설명 자리에 안내 문구가 들어 있어서였고, 그 문구를 걸러 내고 이전 버전의 설명으로 바꿨습니다(405개).

데이터의 예외를 화면 규칙으로 옮긴 것도 많습니다. 세 번째 타입을 고르면 가장 먼저 고른 타입이 빠지고(두 타입은 "모두 가진" 조건), 껍질몬은 HP가 항상 1이라 실능치 패널에서 따로 처리하며, 암수 모습 차이는 메가진화나 이미 암컷인 폼에 표시가 붙지 않도록 기본 폼에만 표시합니다.

## 배운 점

위키 가져오기를 처음 돌렸을 때 절반 가까운 종이 비어 있었고 자리 표시가 설명으로 들어가 있었습니다. 결과를 세어 보고 이상한 값을 찾는 단계가 없었다면 그대로 배포됐을 겁니다.

타입 색을 배지와 막대에만 남기자 오히려 정보가 잘 읽혔고, 배틀과 계산기를 빼자 도감이 뭘 하는 곳인지 분명해졌습니다. 피드백에서 지적받은 곳은 대부분 제가 설명 없이도 알아볼 거라고 넘겼던 곳이었습니다.
