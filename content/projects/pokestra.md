## 개요

1세대부터 9세대까지 모든 포켓몬을 다루는 도감이자 배틀 사이트입니다. 한국어·영어·일본어를 지원하고, 배틀과 데미지 계산은 직접 만든 [pokebattle-engine](/projects/pokebattle-engine/)으로 돌아갑니다.

좋아하는 게임 데이터로 UI를 실험하려고 시작했지만, 만들다 보니 실무에서 하던 일과 같은 문제를 풀고 있었습니다. 1,000개가 넘는 항목을 빠르게 찾게 하고, 숫자가 많은 화면을 읽히게 만들고, 여러 단계로 진행되는 상태를 사용자가 따라오게 하는 일입니다.

## 고민한 것

### 1,000개 넘는 항목을 기다림 없이 찾기

검색할 때마다 API를 부르면 필터 하나 바꿀 때마다 기다려야 합니다. 그래서 PokeAPI에서 필요한 데이터만 골라 JSON으로 만들어 저장소에 커밋하고, 검색과 필터는 모두 브라우저 안에서 처리했습니다. 긴 목록은 화면에 보이는 만큼만 조금씩 그리도록 해 첫 렌더링을 가볍게 유지했습니다.

### 필요한 것만 내려받기

배틀 엔진과 시뮬레이터는 크기가 큽니다. 도감만 보러 온 사람이 이걸 받을 이유는 없어서, 큰 화면은 `React.lazy`로 나누고 엔진과 데이터는 그 화면에 들어갈 때 내려받게 했습니다.

### 상태를 주소에 담기

도감의 검색어와 필터, 계산기의 대결 조합은 URL에 담깁니다. 새로고침해도 보던 화면이 그대로 남고, `?atk=garchomp&def=gholdengo` 같은 링크로 계산 결과를 그대로 공유할 수 있습니다.

### 이벤트를 장면으로 재생하기

엔진은 한 턴의 결과를 이벤트 묶음으로 한꺼번에 돌려줍니다. 이걸 그대로 보여 주면 HP가 한 번에 바뀌어 무슨 일이 있었는지 알기 어렵습니다. 그래서 이벤트마다 장면을 기록해 두고 순서대로 재생하도록 만들어, 기술 사용 → 데미지 → 상태 변화가 로그와 함께 하나씩 보이게 했습니다.

### 빠진 번역을 타입으로 막기

화면 문구는 `defineMessages({ ko, en, ja })`로 정의하고, 영어나 일본어에 빠진 키가 있으면 타입 검사에서 실패하게 했습니다. 포켓몬·기술·특성 이름은 PokeAPI의 언어별 데이터를 써서, 번역을 직접 관리하지 않아도 되게 했습니다. 첫 방문 때는 브라우저 언어를 따르고, 고른 언어는 기억합니다.

### 디자인 시스템 위에서 만들기

UI는 Astryx 디자인 시스템의 테마 토큰 위에 Tailwind CSS v4를 얹어 만들었습니다. `text-primary`, `bg-surface` 같은 유틸리티가 테마 토큰으로 이어지게 해서, 실무에서 [디자인 시스템](/projects/design-system/)을 만들며 정했던 원칙(값을 직접 쓰지 않고 토큰을 쓴다)을 개인 프로젝트에도 그대로 적용했습니다.

## 배포

이 블로그 저장소가 Pokestra의 `main`을 받아 `/portfolio/pokestra/` 경로로 빌드해 함께 게시합니다. 엔진은 GitHub 저장소에서 바로 설치하고, 설치할 때 엔진의 `prepare` 스크립트가 빌드를 마칩니다.

## 배운 점

- 데이터 구조를 먼저 정해야 인터랙션이 단순해진다. 어떤 데이터를 미리 만들어 둘지 정하고 나니 검색과 필터 코드가 짧아졌다.
- 한 번에 바뀌는 상태는 사용자가 따라가지 못한다. 결과를 순서대로 보여 주는 것도 설계다.
- 사이드 프로젝트는 실무에서 시도하기 어려운 구조를 먼저 실험해 보는 곳이다.
