## 개요

AI 탐지 장비와 서비스를 운영하는 관리자 시스템입니다. 고객사와 장비를 관리하고, 단말기 상태를 모니터링하고, 장비에서 돌아가는 AI 모델의 정책을 바꾸는 일을 한 화면 체계 안에서 할 수 있게 만들었습니다.

프론트엔드를 주도했고, 화면 설계뿐 아니라 인증 방식, 타입·테스트 기준, 배포 파이프라인까지 맡았습니다.

## 맡은 범위

| 영역 | 내용 |
|---|---|
| 화면 | 고객사·장비 관리, 단말기 모니터링, AI 모델 정책, ROI 편집, 변경 이력 |
| 보안 | MFA 인증, HttpOnly 쿠키 기반 인증 |
| 품질 | TypeScript 엄격화, 자동화 테스트 |
| 배포·운영 | GitHub Actions 배포, 배포 전 백업, 장애 대응 |

## 문제

관리자 화면은 기능이 늘어날수록 메뉴와 표가 늘어나기 쉽습니다. 하지만 운영자가 실제로 알고 싶은 것은 "지금 문제가 있는 장비가 있는가", "방금 바꾼 정책이 무엇을 바꿨는가" 같은 몇 가지 질문입니다. 데이터를 많이 보여 주는 화면이 아니라, 운영자가 빨리 판단하게 돕는 화면을 목표로 했습니다.

## 한 일

### 운영과 모니터링

- 고객사와 장비 관리
- 단말기 운행·통신 상태 모니터링
- 상태 요약 → 알림 → 목록 → 상세 순으로 정보 우선순위를 정리해, 이상이 있는 장비가 먼저 눈에 띄게 구성

### AI 모델 정책

- AI 모델별 탐지 정책, 추론 모델, 임계값 관리
- 이미지 위에서 ROI(관심 영역)를 직접 그리고 고치는 편집 화면
- 정책 변경 이력 조회와 이전·이후 값의 차이 시각화

임계값이나 관심 영역을 바꾸면 장비가 찾아내는 결과 자체가 달라집니다. 그래서 바꾸는 화면만큼, 무엇을 언제 바꿨는지 되짚어 보는 화면이 중요했습니다.

### 보안

- MFA 기반 로그인
- 인증 토큰을 자바스크립트에서 읽을 수 없는 HttpOnly 쿠키로 옮겨, 스크립트 삽입 공격이 생겨도 토큰이 새지 않게 함

### 품질과 배포

- TypeScript 엄격 모드로 전환하고 타입 오류 정리
- 자동화 테스트 구성
- GitHub Actions 기반 배포 파이프라인
- 배포 전 백업 절차를 두고, 운영 중 장애에 대응

## 직접 내린 결정

- **로딩·빈 상태·오류 상태를 기능으로 설계.** 장비 데이터는 늦게 오거나 비어 있거나 실패하는 일이 흔합니다. 이 상태들을 화면마다 따로 처리하지 않고 같은 모양으로 보여 주게 했습니다.
- **인증을 쿠키 기반으로 바꾸기.** 관리자 시스템은 권한이 큰 만큼, 편의보다 토큰이 노출되지 않는 쪽을 택했습니다.
- **타입과 테스트를 먼저.** 여러 사람이 오래 고칠 화면이라, 기능을 더하기 전에 바뀐 것이 다른 곳을 깨뜨리지 않는지 확인할 장치부터 갖췄습니다.

## 배운 점

- 정보 구조 설계가 UI의 절반이다.
- 보여 주는 화면과 실제로 쓰이는 화면은 다르다.
- 실시간으로 바뀌는 데이터일수록 안정감 있게 표현해야 한다.
