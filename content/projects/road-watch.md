## 한눈에

| 항목 | 내용 |
|---|---|
| 맡은 일 | 배분받은 프론트엔드 기능 구현과 보안 요구사항 대응 |
| 영역 | MFA 인증, RSA-OAEP 요청 암호화, 세션 관리, 현장 등록 |
| 환경 | NCP와 AWS |
| 보안 기준 | CSAP(클라우드 보안 인증) 관련 요구사항 |

## 개요

도로 현장 작업자가 쓰는 앱에서 인증·보안과 현장 등록 기능을 맡았습니다. 전체 프론트엔드 구조를 설계한 프로젝트는 아니고, 배분받은 기능을 구현하면서 보안 요구사항에 맞춰 대응한 프로젝트입니다.

## 한 일

### MFA 인증

- 다중 인증을 적용한 로그인 흐름
- MFA 등록과 검증 단계에 따른 화면 상태 처리
- 인증 상태에 따른 화면·기능 접근 처리
- 인증 실패와 인증 만료 예외 처리

### 요청 암호화

- RSA-OAEP 기반 요청 암호화 적용
- 보안 요구사항에 맞춘 API 요청 처리
- 암호화를 적용하면서 생기는 요청 데이터 처리 문제 검토
- 인증과 암호화가 함께 정상 동작하는지 검증

### 세션과 사용자 상태

- 인증 토큰과 세션 수명 관리
- 인증 실패 시 사용자 상태 초기화
- 세션 만료와 재인증 흐름
- **인증 상태와 실제 화면 접근 권한이 어긋나지 않게** 처리

### 현장 작업

- 현장 등록 화면과 입력값 검증
- 서버 API와 등록 데이터 연동
- 현장 작업 중 생기는 예외 처리

### 클라우드 환경

- NCP와 AWS 환경 차이에 따른 기능 대응
- CSAP 관련 보안 요구사항에 맞춘 구현과 검토
- 인증·통신 환경에 따른 문제 분석

## 직접 내린 결정

| 문제 | 대응 |
|---|---|
| 단일 인증 방식의 한계 | MFA 인증 단계 도입 |
| 요청 데이터 보호 | RSA-OAEP 기반 암호화 |
| 인증 만료와 접근 제어 | 세션 상태와 화면 접근 흐름 연동 |
| 클라우드별 환경 차이 | 환경별 요청·설정 대응 |
| 보안 요구사항 | 인증·요청·세션 전반 검토 |

CSAP 관련 요구사항에 맞춰 대응했고, 인증 자체를 취득한 것은 아닙니다.

## 배운 점

- 인증과 폼은 기능이 아니라 흐름이다. 로그인, 추가 인증, 세션 만료가 하나의 경험으로 이어져야 한다.
- 보안 기준을 지키면서도 사용자가 헷갈리지 않게 안내하는 일이 따로 필요하다.
- 이미 돌아가는 시스템에 기능을 더할 때는, 새 코드보다 기존 흐름을 먼저 이해하는 시간이 더 길다.
